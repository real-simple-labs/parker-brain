# Process — Design the Hierarchy

Set what the eye lands on first, second, third — and assign the lever that enforces each step. **This runs on every static.** A spec that lists copy and a product shot without a read order is not a finished static; it is a mood board.

The reason this matters: nobody reads a static top to bottom. They scan, land on whatever is most appealing, and go from there — and not in the order the designer assumed. That is controllable, and controlling it is the difference between a message that gets read and one that does not.

## Statics have hooks

A hook is not a video concept. On a static, the hook is whatever the eye lands on first, and it should be the most arresting thing on the ad.

The worked example: an ad whose largest element reads "Faking it with my husband." That lands first — it is a hook, and it stops the scroll. Then a qualifying line that tells the reader whether this is about them. Then the product. Then the social proof. Had the social proof been placed first, a stranger would have thought "I don't know this brand" and kept scrolling, because the ad would have opened with its least interesting claim.

## The default read order

**Hook → qualifier → product → proof.**

This is the reliable default for an acquisition static, and the reason is the stranger: they need to be stopped, then told whether this concerns them, then shown what it is, and only then given a reason to believe. Proof is last because proof is meaningless before interest.

Depart from it deliberately and say why. A bottom-funnel offer static legitimately leads with the offer. A press static legitimately leads with borrowed credibility, because the credibility *is* the hook.

## The three levers

- **Sizing.** The biggest thing is read first. The bluntest lever and the most powerful. If the intended hook is not the largest element, nothing else will save the hierarchy.
- **Contrast.** A color break isolates an element from its surroundings. Use it to pull one element out of a field, or to make a single word inside a line carry weight.
- **White space.** Space around an element makes it land; crowding buries it. Under-used, because empty space feels like waste until you watch someone scan.

Every step in the read order gets a lever assigned. If you cannot name which lever enforces a step, that step is not enforced.

## The elements available

Placement and sizing of images. Placement and sizing of headlines. The words themselves. Fonts and colors. Warps and distortions. Highlights and arrows.

These read as small decisions and are not. The worked example: two versions of the same nerve-pain ad. On the left, "nerve pain killer" set with no color, "killer" running across a white highlight so it fights to be read. On the right, the same words broken onto two lines with a red block behind "killer" — red connoting danger, the line break making it legible in one pass. Same copy. The second is dramatically easier to take in, and first impression is all a static gets.

## Execution

1. **Name the hook.** Which single element must land first. Usually the headline or the customer quote.
2. **Write the read order** as an ordered list of elements.
3. **Assign a lever to each step.** Sizing for the hook, then whichever of contrast and white space enforces the rest.
4. **Check legibility at feed size.** Every word must be readable in one pass on a phone. Long quotes need the size the design gives them, which usually means less of everything else.
5. **Check the reverse.** Ask what a stranger's eye would *actually* hit first given the sizes assigned. If it is the logo, the proof strip, or the product, the hierarchy is inverted.
6. **Match the aspect ratio to the placement.** 1:1, 4:5, 9:16, 16:9 serve different placements and a hierarchy that works in one can collapse in another.

## Output content

- The hook, named.
- The read order, as an ordered list.
- The lever enforcing each step.
- Any typographic treatment doing real work — line breaks, color blocks, highlights — and what each is for.
- The aspect ratio and the placement it is for.

## What never to do

- Ship a static with no stated read order.
- Make the proof, the logo, or the brand name the largest element on an acquisition static.
- Assign an order without assigning the levers that enforce it.
- Assume a hierarchy that works at full size survives at feed size.
- Break the default order without saying why.
