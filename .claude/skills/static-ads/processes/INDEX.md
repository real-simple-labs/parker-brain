# Static Ads — Process Index

`strategy.md` picks from these. Most statics run three: one from Phase A, one idea path from Phase B, and then the Phase C chain.

## Phase A — Find the play

- **`find-white-space.md`** — read the account for what it is not saying. Format, persona, awareness, and the demographic-versus-creative read. Runs first on every open ask.
- **`reverse-engineer-winning-static.md`** — take an external static holding a top impression rank and rebuild its mechanism with this brand's copy and proof.
- **`build-the-swipe-file.md`** — assemble or refresh a queryable library of statics worth stealing from, organized by format tag.

## Phase B — Write the message

- **`static-from-customer-language.md`** — a golden nugget from reviews or comments becomes the ad, unparaphrased. The default idea path.
- **`persona-static.md`** — one persona, named or shown, with the whole message built for them alone.
- **`make-the-invisible-visible.md`** — a felt sensation from customer language rendered as an intentionally unrealistic visual.
- **`atypical-text-placement.md`** — the copy written on an unexpected but category-relevant surface.

## Phase C — Design and produce

- **`design-the-hierarchy.md`** — set the read order and assign the three levers. **Runs on every static, no exceptions.**
- **`produce-the-static.md`** — render the asset through a connected image-generation MCP, or degrade to prompt text and name what is missing.
- **`judge-the-render.md`** — grade the finished image against the quality checklist. The spec passing is not the render passing.
- **`deliver-to-slack.md`** — put the finished statics in a channel. Optional.
