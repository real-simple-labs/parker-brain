# v25 — `parker-context/` is read-only and stays out of the repo

**Applies to:** every brain.

**What changes:** Parker is moving the documents it keeps in its own database (first the brand context) into a folder of the brain, `parker-context/`. Parker Desktop will write them there, read-only; they never go through the repo, because Parker's database is where they live and change. This release gets every brain ready before the first file arrives: git ignores the folder, and neither runtime's edit tools may write into it. The re-sync delivers the permission rules (`.claude/settings.json`, `.codex/config.toml`); the `.gitignore` is the brain's own file, so step 1 adds the line.

## Step 1 — add `parker-context/` to `.gitignore`

At the brain's root, add this line to `.gitignore`, and create the file when there is none:

```
parker-context/
```

Leave every other line alone. If the file already ignores the folder (the exact line, or `/parker-context/`), there is nothing to do.

Verify: `grep -qxE '/?parker-context/?' .gitignore && echo ok` prints `ok`.

## Step 2 — team-edited copies the re-sync left alone

The re-sync refreshes untouched files by itself. For each file below that its report lists as team-edited, show the team the change and apply just this part, leaving the rest theirs:

- **`.claude/settings.json`**: add four entries to `permissions.deny`: `"Edit(/parker-context/**)"`, `"Edit(parker-context/**)"`, `"Write(/parker-context/**)"`, `"Write(parker-context/**)"`.
- **`.codex/config.toml`**: under `[permissions.parker-brain.filesystem.":workspace_roots"]`, add `"parker-context" = "read"` next to the `parker-system` line. A brain whose Codex runs a legacy `--sandbox` or `sandbox_mode` has no such profile; skip it there.

Record `v25` once both steps are done.
