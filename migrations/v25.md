# v25 — `parker-context/` stays out of the repo

**Applies to:** every brain.

**What changes:** Parker is moving this brand's context documents that it keeps in its own database (first the brand context) into a folder of the brain, `parker-context/`. Parker Desktop will keep that folder in sync with the database, in both directions, so the team and their agents can read and edit the files like any other. They never go through the repo: Parker's database is where they live, and a second copy in git could disagree with it. This release gets every brain ready before the first file arrives: git ignores the folder. The `.gitignore` is the brain's own file, so the re-sync can't add the line; this migration does.

## Step 1 — make room for `parker-context/`

First check that the brain doesn't already hold a folder with this name: `git ls-files -- parker-context/` (it only reads). If it lists files, the team made a `parker-context/` of their own before Parker reserved the name, and the ignore rule would leave those files stranded in the repo while Parker Desktop fills the folder from the database. Show the team the list, ask which folder the files should live in instead (for example `team-context/`), and move them there with an ordinary file move, not a git command. The sync saves the move, so every teammate gets the files in their new place. Never take them out of git where they are (`git rm --cached`): a teammate's copy deletes files that leave the repo, on its next sync.

## Step 2 — add `parker-context/` to `.gitignore`

At the brain's root, add this line to `.gitignore`, and create the file when there is none:

```
parker-context/
```

Leave every other line alone. If the file already ignores the folder (the exact line, or `/parker-context/`), there is nothing to add.

Verify: `grep -qxE '/?parker-context/?' .gitignore && echo ok` prints `ok`, and `git ls-files -- parker-context/` prints nothing.

Record `v25`.
