# v46 — installed packages and build output stay out of the brain

**Applies to:** every brain, scaffolded brains included.

**Auto-apply:** yes. One step adds the ignore rules the brain's `.gitignore` lacks. It never removes or changes a line, and it never takes a file out of the brain.

**What changes:** An agent that sets up a code project inside a brain (a small web app, a script and its packages) can save thousands of files nobody needs: installed packages, build output and caches. They make the brain slow to save, sync and list, and the project's install or build command makes them again. New brains get the rules from the scaffold's `.gitignore`. The `.gitignore` is the brain's own file, so the re-sync can't add them here; this migration does. Raw data, run output and logs are not on the list: teams keep those on purpose.

## Step 1 — add the build rules to `.gitignore`

These are the rules, in this order:

```
node_modules/
.next/
.nuxt/
.vercel/
.parcel-cache/
.venv/
__pycache__/
.pytest_cache/
.mypy_cache/
*.js.map
*.mjs.map
*.cjs.map
*.jsx.map
*.ts.map
*.css.map
```

At the brain's root, read `.gitignore` (when there is none, start an empty one). A rule is there already when the file has a line that matches it with or without a leading or trailing `/` (`/node_modules`, `node_modules` and `node_modules/` all count for `node_modules/`). If every rule is there, skip the step.

Otherwise, at the end of the file, add one empty line (not in a new, empty file), then these three comment lines, then the rules that aren't there yet, in the order above:

```
# Installed packages, build output and caches from code projects. The
# project's install or build command makes them again, so they aren't
# saved here. Raw data, run output and logs are still saved.
```

Leave every other line as it is. Don't take any file out of git: files under these paths that the brain holds already stay saved, and an ignore rule only stops new ones. (`git rm --cached` would delete them from every teammate's copy on their next sync.)

Verify: this prints `15`.

```
git check-ignore --no-index -v node_modules/x .next/x .nuxt/x .vercel/x .parcel-cache/x .venv/x __pycache__/x .pytest_cache/x .mypy_cache/x x.js.map x.mjs.map x.cjs.map x.jsx.map x.ts.map x.css.map | grep -c '^\.gitignore:'
```

It only reads. A number below 15 means a rule is still missing from `.gitignore`.

Record `v46`.
