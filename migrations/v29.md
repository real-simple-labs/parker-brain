# v29 — the brand context and the context docs are files of the brain

**Applies to:** every brain, scaffolded ones too.

**What changes:** Parker keeps this brand's brand context (the document its chat reads in every conversation) as `brand-context/brand-context.md` in the brain. It is an ordinary tracked file: Parker commits its own changes to it, and an edit the team saves here becomes what Parker knows. The same folder holds the brand's own context docs from Parker, one file per doc named after the doc (`brand-context/<doc name>.md`), synced the same way. Parker writes the files itself on its first sync, which may come after this release; until then the folder isn't there, and the map lines say so. This migration doesn't create the files. It only tells the brain's `CLAUDE.md` where they are. The `CLAUDE.md` is the brain's own file, so the re-sync can't add the line; this migration does.

## Step 1 — name the folder in the map

In `CLAUDE.md`, under `## The map`, look for each of the two lines below on its own: one that names `brand-context/brand-context.md`, and one that names `brand-context/<doc name>.md`. Add each line that isn't there and leave a line that is. When both are there, this step has nothing to do.

Put a missing line where it belongs: the `brand-context/brand-context.md` line right after the `brand-lens.md` line (or at the end of the map's list if the team removed that line), and the `brand-context/<doc name>.md` line right after the `brand-context/brand-context.md` line. The two lines:

```
- `brand-context/brand-context.md` — when it is here, the brand context: the document Parker's chat reads for this brand in every conversation. Parker writes it into the brain and keeps it in sync both ways, so an edit saved here becomes what Parker knows, and a change made in Parker (the brand context generation, the team's or Parker's support's edits) arrives here as a commit from Parker. Read it early on any brand question. If the folder isn't here, Parker hasn't synced this brain yet: don't create the file yourself (nothing would read it), and put what you'd write there into `brand-lens.md` or the running notes instead. The folder says nothing about whether this brain is built.
- `brand-context/<doc name>.md` — when they are here, this brand's context docs from Parker, one file per doc, named after the doc ("Visuals 2.0" is `Visuals 2.0.md`). Parker's chat reads a doc when a question needs it, and the files sync both ways like the brand context, so an edit saved to one becomes that doc in Parker. Keep the file names: Parker knows each doc by its file, so a renamed file is a new file Parker doesn't read, and the old name comes back. A new file put in this folder becomes no doc: put new material in the brain's own folders.
```

Change nothing else in `CLAUDE.md`.

Verify: this prints `ok`.

```
grep -q 'brand-context/brand-context.md' CLAUDE.md && grep -q 'brand-context/<doc name>.md' CLAUDE.md && echo ok
```
