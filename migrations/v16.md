# v16 — Parker Desktop owns the sync: no more git in the brain

**Who this applies to:** every standing brain on the standard layout (pinned `parker-system/` submodule). Decoupled and self-managed brains (origin outside `parker-brain/`) skip steps 2–4 — their team owns their sync — but step 1 still applies if a stale credential file exists.

**What changes:** the brain stops syncing itself. The Parker Desktop app (https://app.heyparker.ai/dashboard/parker-desktop) watches the brain's folder and syncs every change both ways, so saving is just writing files — no credentials, no pulls, no pushes, no `setup_parker_brain` provisioning. The pin bump's re-sync delivers the rewritten `save-brain` skill, the new `git-guard.py` (blocks git aimed at the brand repo; mount operations pass), the simplified `session-start.py` (no more start-of-session pull), and the updated bundle READMEs. This migration handles what the sync can't rewrite.

## Step 1 — remove the old credential file

From the brain's root folder:

```bash
rm -f .git/parker-credentials
```

Safe — the command carries no secret, and the file only ever held a short-lived token that is long dead.

## Step 2 — tell the team about Parker Desktop, before anything else changes behavior

Say it plainly, in Parker's voice: the brain now saves itself through the Parker Desktop app — install it from https://app.heyparker.ai/dashboard/parker-desktop, sign in, and connect it to this brand so it adopts this folder. Until the app is running, changes stay on this machine only; say that honestly rather than letting the team believe work is backed up. Don't run the old credential flow as a stopgap — it's retired.

## Step 3 — settings.json, only if the team edited it

The re-sync refreshes an untouched `.claude/settings.json` automatically. If the sync report listed it as team-edited, show the team and remove the four retired credential entries from `permissions.allow` (leave everything else theirs):

- `"Write(.git/parker-credentials)"`
- `"Write(/.git/parker-credentials)"`
- `"Write(//tmp/parker-credentials)"`
- `"Bash(rm -f .git/parker-credentials)"`

## Step 4 — refresh the git sections in the brain's root `CLAUDE.md`

The root `CLAUDE.md` is brand-authored, so nothing re-syncs it. Two spots to rewrite, matching the current template (`parker-system/templates/brand-brain-CLAUDE-template.md`):

1. The **"How this brain saves itself"** section — replace its git-procedure paragraphs with the template's current version (Parker Desktop syncs the folder; write files and they're saved; never git against this repo; the mount carve-out; what to do when the folder isn't syncing).
2. The **ground-truth bullet** that starts "Git is plain `git`, never the `gh` CLI" — replace it with the template's current "Never run git here" bullet.

Also refresh the `parker-voice` block while in the file if it drifted (`python3 parker-system/scripts/sync-open-loops-core.py --scan .`).

## Verify

- `.git/parker-credentials` is gone.
- `.claude/hooks/git-guard.py` mentions Parker Desktop (the re-sync brought the new one).
- In a managed repo, `echo '{"tool_name":"Bash","tool_input":{"command":"git push origin main"}}' | python3 .claude/hooks/git-guard.py` prints the teaching message and exits 2, while `echo '{"tool_name":"Bash","tool_input":{"command":"git -C parker-system fetch --tags"}}' | python3 .claude/hooks/git-guard.py` exits 0.
- The root `CLAUDE.md` no longer mentions credential files or push/pull procedure.

Record migrations through `v16` and set `parker_brain_version` to `v16` as usual.
