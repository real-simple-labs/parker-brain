# v40 — safe releases install on their own

**Applies to:** brains on the standard layout (pinned `parker-system/` submodule, posture `follow`). A decoupled brain (posture `own-factory` or `independent`) skips every step: automatic updates never apply to it. Record `v40` there and stop. Scaffolded brains run every step; none of them touches built content.

**Auto-apply:** no. This release is the team's yes to automatic updates, so it is always offered, never taken on its own.

**What changes:** from this release on, `/update-brain` installs a new release without asking when every migration on the way is safe to run unattended (a no-op, or marked `**Auto-apply:** yes`), automatic updates are on in the ledger, no build is underway, and nothing earlier is unfinished. The new `parker-system/scripts/update-brain.py` decides that (`plan`) and keeps the ledger honest while the update runs (`record-migration` never skips one; `record-pin` only records the tag the mount is on). A migration that needs a person, a decoupled brain, or a team that turned automatic updates off still gets one short question. The team's edits stay theirs exactly as before: the sync script refreshes only copies they never touched. The re-sync delivers the new `update-brain` skill and schedule recipe; this migration handles the ledger, the brain's `CLAUDE.md`, and the armed routine, which the re-sync can't reach.

When you offer this release, say it plainly in the one question: "From now on, safe Parker updates install themselves and I'll tell you what changed. Anything that touches your own docs still waits for your OK."

## Step 1 — add the setting to the update ledger

In `running-notes/standard-sync.md`, if there is no line that starts with `- **Auto-update:**`, add this line right under the `- **Posture:**` line:

```
- **Auto-update:** on
```

If the team said, when they took this release, that they want to OK each update themselves, write `off` instead, and add a line to the offer history saying so. If the line is already there, leave it as it is. If the ledger has no `- **Posture:**` line, add it at the end of "Where this brain stands" and say so in the summary. Change nothing else in the ledger.

Verify: this prints one line.

```
grep -c '^- \*\*Auto-update:\*\*' running-notes/standard-sync.md
```

## Step 2 — one sentence in CLAUDE.md

The root `CLAUDE.md` is the brain's own, so show the team the change before applying it. In `CLAUDE.md`, replace:

```
updates arrive only through `/update-brain` offering a newer release,
```

with:

```
updates arrive only through `/update-brain` moving it to a newer release (safe releases install on their own; the rest are offered),
```

If the text isn't there (the team rewrote the sentence), skip this step. A "not now" skips it too, and doesn't stop the migration: the sentence is a description, not a rule the brain runs by. Change nothing else in `CLAUDE.md`.

## Step 3 — offer to re-arm the update routine

A routine armed before v40 carries the old prompt, which ends "apply nothing — offers wait for the user". The skill honors that, so a scheduled run with the old prompt keeps offering instead of installing.

1. List this account's live schedules via `/schedule`. If none is this brand's update routine armed by `/setup-routines` ("[brand]: update-brain", or a prompt that runs `/update-brain` for this brand), skip this step.
2. If its prompt still says "apply nothing — offers wait for the user", offer once to re-arm it with `/setup-routines`, following the copy in the mount, `parker-system/templates/brand-routines/claude/skills/setup-routines/SKILL.md`, and the recipe in `parker-system/templates/brand-routines/schedules/update-brain.md` (migrations run before the re-sync, so the brain's own copies can still be the old ones). Say why in a sentence: with the new prompt, the Monday run installs safe updates itself instead of leaving them for someone to approve.
3. A yes (and the re-arm done), a no, or a "not now" all finish this step: record the answer in the ledger like any other offer. Routines armed from a teammate's account, and routines the team made themselves, aren't touched.

Record `v40`.
