# v22 — clashes are combined in the files; `git add`, `commit` and `merge` pass the guard

**Applies to:** brains pinned at `v21` or earlier. No-op on `v22+`.

**What changes:** Parker Desktop (the release after 0.15.4) settles a clash - the same lines changed here and on the shared copy - by putting both versions into the files itself, between git's `<<<<<<<` and `>>>>>>>` marks, and hands the assistant a request to edit the files until no mark is left. The app then saves and shares the result, so the assistant needs no git for it. For this one situation the guard (`git-guard.py`) lets `git add`, a plain `git commit` and `git merge` through from this release, so finishing a combine by hand is never blocked halfway; `push`, `pull`, `fetch`, `rebase`, `commit --amend`, `merge --abort` and `merge --quit` stay blocked. `save-brain`, the brand `AGENTS.md`, `session-start.py` and `system/brain-sync.md` describe the flow.

**Nothing to do on the brand side.** Everything above travels in the copied bundle, so the pin bump's re-sync delivers it. The brand root `CLAUDE.md` sentence "never run git against this repo" stays true as the default and needs no edit; the template's new sentence about clashes is optional wording, not a rule change. Record `v22` and set `parker_brain_version` to `v22` as usual.
