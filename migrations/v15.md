# v15 — fine-tuned skills, and the precedence rule that makes the brain route to them

**Applies to:** brains pinned at `v14` or earlier.

This release adds the fine-tuned-skill pattern: a brand-authored skill built from the team's own corpus, living beside the copied factory skill under a distinct name, taking precedence over it for that craft. The method doc (`parker-system/system/growing-the-brain.md`) rides the mount and arrives with the pin bump — nothing to do for that half.

The half that needs a step is precedence. It has to be live in the brain's root `CLAUDE.md`, which sits outside `parker-system/` and outside the sync script's bundle map, so nothing delivers it automatically. Without it a team can build a perfect fine-tuned skill and the planning pass will keep routing to the generic one.

**Only the root `CLAUDE.md` changes here. No skill is created, moved, renamed, or edited by this migration** — building a fine-tune is the team's call, made when they have a corpus worth building on.

## Step 1 — add the precedence rule to the brain's root `CLAUDE.md`

**This edits brand-authored content: show the team the diff and get an OK before writing.**

Find the execution-routing bullet under **## Match the ask — calibration**. It begins `- **Anything execution-shaped routes through a skill.**` and ends with the sentence about a copied file being frozen at the team's version while the factory's copy moves on.

Check first — if the phrase `fine-tuned sibling` already appears in the file, this step is done; skip to Step 2.

Two edits inside that bullet.

**1a.** Replace the sentence beginning `Edit a copied skill or schedule file directly only when the adaptation truly can't live in a brand doc:` with the fuller ladder:

> When the difference is a real process difference and the team has a corpus of their own work behind it, build a **fine-tuned sibling skill** instead: a brand-authored skill under a distinct name (`<brand>-scriptwriting`, never `scriptwriting`) that references the factory skill and states what is different here. It keeps taking factory improvements through the skill it references, and the distinct name keeps it outside the update sync's bundle map so it stays yours permanently. The method is `parker-system/system/growing-the-brain.md`. Edit a copied skill or schedule file directly only when neither of those works: a file you edit is yours from then on, and `/update-brain` will leave it frozen at your version while the factory's copy moves on.

**1b.** Immediately after that bullet, add the precedence paragraph as its own line:

> **Where a fine-tuned skill exists for a craft, it is the default for that craft** — route to it, and treat the factory skill as the method underneath it and the fallback. Where none exists, the factory skill is the default. Fine-tuned skills are listed in "## The map" above; if one is there, the planning pass routes to it rather than the generic version.

If the team has customized that bullet past recognition, keep their wording and append only the precedence paragraph — the routing rule is the load-bearing part, not the exact sentence.

Verify: `grep -n "fine-tuned" CLAUDE.md` returns both the ladder sentence and the precedence paragraph.

## Step 2 — extend the `.claude/skills/` line in "## The map"

Same file, the `.claude/skills/` bullet under **## The map**. Append to the end of that bullet:

> Any **fine-tuned skill** this team has built from their own corpus lives here too, under a distinct name, and takes precedence over the factory skill it specializes — list each one here as it is built.

Skip if the bullet already says it. If the brain already has brand-authored skills in `.claude/skills/` that aren't in the sync bundle map, name them on that line now — they are exactly what this rule is for, and an unlisted one won't get routed to.

Verify: `ls .claude/skills/` against the factory skill names; anything extra should appear in the map line.

## Then

Record migrations through `v15` and set `parker_brain_version` to `v15` as usual.
