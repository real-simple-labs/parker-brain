# v14 — second-person identity in the brain's own CLAUDE.md, and switching on the voice layer

**Applies to:** brains pinned at `v13` or earlier.

Two pieces of this release land outside the copied bundle, so the pin bump alone doesn't deliver them. The rest — the new creative-strategy knowledge docs, the regenerated craft catalog the prompt hook injects, the output-style file itself — rides the mount or the re-sync and needs nothing.

## Step 1 — refresh the voice block in the brain's root `CLAUDE.md`

The brain's root `CLAUDE.md` sits outside `parker-system/`, so nothing rsyncs it. It carries the canonical Parker voice between the `parker-voice` start/end HTML-comment markers, and that block was rewritten this release: third person about a character became second person to the model reading it.

From the brain's **root folder**, check first, then apply:

```bash
python3 parker-system/scripts/sync-open-loops-core.py --check --scan .
python3 parker-system/scripts/sync-open-loops-core.py --scan .
```

The script writes only where a block actually drifted, so it's safe to re-run and safe to run on a brain that's already in step ("Nothing to do" is a passing result). Everything it finds under `parker-system/` is already at the new tag and won't be touched.

## Step 2 — turn the identity lines outside that block to second person

Three spots in the brain's root `CLAUDE.md` say "Parker" in the third person. They sit outside the synced markers, in brand-authored text, so Step 1 leaves them behind — and a file that's second person inside the block and third person around it is exactly the drift this release exists to kill.

**These edits touch brand-authored content: show the team the diff and get an OK before writing.** Skip any spot whose wording the brand has already customized past recognition; the point is the person, not the exact sentence.

1. The opening identity paragraph, near the top:
   - `You are **Parker**, a senior creative strategist operating as **<Brand>'s brain**.` → `You are a senior creative strategist operating as **<Brand>'s brain**. The team calls this system **Parker**; when anyone asks what Parker thinks, that's you.`
   - later in the same paragraph: `everything Parker knows about <Brand>` → `everything you know about <Brand>`
2. The `users/[user-id]/user-profile.md` bullet in **The map**: `how they like Parker to work` → `how they like you to work`, and `as they use Parker` → `as they work with you`.
3. The Parker-MCP-not-connected bullet in the rules: `remind the user that Parker needs some way to reach that data` → `remind the user that you need some way to reach that data`.

Leave every artifact name alone — `Parker MCP`, `parker-system/`, `parker-brain`, `setup_parker_brain`, `/save-brain` are names, not third-person references.

Verify: `grep -n "Parker" CLAUDE.md` should return only artifact names, the "the team calls this system Parker" mapping line, and whatever the voice block itself says.

## Step 3 — after the sync script runs, confirm the voice layer is actually switched on

This one is a check, not a copy. `scripts/sync-executable-layer.py` runs at the end of `/update-brain` and owns both halves of the voice layer: it adds `.claude/output-styles/parker.md` and refreshes `.claude/settings.json`, which now carries `"outputStyle": "Parker"`. But the script deliberately won't overwrite a file the team has edited — and if the brain's `settings.json` was touched locally, the script reports it under **"left alone — the team changed these, theirs wins"** and the switch never lands. The style file arrives and sits inert.

So, once the sync has run: if `settings.json` was in that left-alone list, open it and confirm the `outputStyle` key is present at the top level, next to `permissions`:

```json
"outputStyle": "Parker",
```

Add just that one line if it's missing. Change nothing else in the file — their edits win. If the script refreshed the file normally, the key is already there and there's nothing to do.

Verify: `grep -n '"outputStyle"' .claude/settings.json` returns the line, and `.claude/output-styles/parker.md` exists with `name: Parker` in its frontmatter. The two have to agree — the switch names the style, the file provides it.

Record migrations through `v14` and set `parker_brain_version` to `v14` as usual.
