# v18 — Parker Desktop owns the sync: no more git in the brain

**Applies to:** brains pinned at `v17` or earlier on the standard layout (pinned `parker-system/` submodule, origin under `parker-brain/`). Self-managed brains (any other origin) keep their own sync: they skip "Before taking this update" and steps 1–2, and do steps 3–5 only where their files carry the managed-brain wording.

**What changes:** the brain stops syncing itself. The Parker Desktop app (https://app.heyparker.ai/dashboard/parker-desktop) keeps a copy of the brain in its own workspace and syncs every change there both ways, so saving is just writing files — no credentials, no pulls, no pushes, no `setup_parker_brain`. The re-sync delivers the rewritten `save-brain` skill, the new `git-guard.py` (blocks git aimed at the brand repo in both runtimes; mount operations pass), the simplified `session-start.py` (no start-of-session pull), the updated `update-brain`, `disconnect-factory`, and `get-started` skills, the brand `AGENTS.md`, and the bundle READMEs. This migration handles what the re-sync can't. The maintainer contract is `parker-system/system/brain-sync.md`.

## Before taking this update — be in the Parker Desktop copy

Read this before offering the update. Parker Desktop does not take over a folder someone cloned by hand; it downloads the brain into its own workspace, at `<root>/orgs/<org>/<repo>/` under the `root` named in `~/.parker/workspace.json`. An update applied anywhere else is never saved.

- **This session is already under that `root`** → go ahead.
- **It isn't** (an older hand-cloned folder, or the app isn't installed) → don't take the update here. First check that this folder holds nothing unsaved: `git status --short --branch` should show no changed files and no `ahead` count. If it does show some, save them one last time with the brain's current `/save-brain`, which is still the old procedure because the re-sync hasn't run. Then tell the team plainly: install Parker Desktop, sign in, and let it download the brain; from then on, work in that copy, and run `/update-brain` again from there. Keep the old folder until the team has seen its work in the app's copy, then retire it.

**Brains taking several releases at once:** `migrations/v16.md` step 2 says to commit the skills symlink per `/save-brain`. Under this release that step is already done: the symlink saves with everything else. Don't run the retired credential flow for it.

## Step 1 — remove the old credential file

From the brain's root folder:

```bash
rm -f .git/parker-credentials
```

Safe — the command carries no secret, and the file only ever held a short-lived token that is long dead. In the app's fresh copy it usually doesn't exist at all.

## Step 2 — turn off submodule recursion

Builds before this release set `submodule.recurse` on the brain. Parker Desktop updates the mount as its own step after every sync, and with this setting on, git reaches into the mount during the app's rebases and restores. From the brain's root folder:

```bash
git config --unset submodule.recurse || true
```

A local setting only; nothing to save.

## Step 3 — team-edited copies the re-sync left alone

The re-sync refreshes untouched files automatically. For each file below that its report lists as team-edited, show the team the change and apply just this part, leaving the rest theirs:

- **`.claude/settings.json`** — remove the four retired credential entries from `permissions.allow` (and the empty `allow` list if nothing else is left): `"Write(.git/parker-credentials)"`, `"Write(/.git/parker-credentials)"`, `"Write(//tmp/parker-credentials)"`, `"Bash(rm -f .git/parker-credentials)"`.
- **`AGENTS.md`** (root) — replace the "Git here follows `/save-brain` exactly" bullet with the current template's "Saving is Parker Desktop's job, not git's" bullet (`parker-system/templates/brand-routines/AGENTS.md`).

## Step 4 — refresh the git sections in the brain's root `CLAUDE.md`

The root `CLAUDE.md` is brand-authored, so nothing re-syncs it. Two spots to rewrite, matching the current template (`parker-system/templates/brand-brain-CLAUDE-template.md`):

1. The **"How this brain saves itself"** section — replace its git-procedure paragraphs with the template's current version (Parker Desktop syncs the folder; write files and they're saved; never git against this repo; the mount and `/disconnect-factory` carve-outs; what to do when the folder isn't syncing).

## Step 5 — tell the team once

In Parker's voice: the brain now saves itself through Parker Desktop. A teammate installs the app and gets the same brain; nobody needs GitHub or git. Codex users need no new hook approval: only the scripts behind the hooks changed.

## Verify, after the re-sync

- `.git/parker-credentials` is gone, and `git config --get submodule.recurse` prints nothing.
- `.claude/hooks/git-guard.py` mentions Parker Desktop.

- The root `CLAUDE.md` and `AGENTS.md` no longer mention credential files or push/pull procedure.
- A minute after the last write, `git status --short --branch` shows no changed files and no `ahead` count: the app saved the update.
