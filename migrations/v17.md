# v17 — the brain opens in OpenAI Codex

**Applies to:** brains pinned at `v16` or earlier (apply `v16.md` first if the pin is older).

This release gives every brand brain a Codex twin: the same hooks wired through `.codex/config.toml`, the same skills discovered through an `.agents/skills` symlink, and the Parker voice carried by a root `AGENTS.md`. The contract is `parker-system/system/codex-support.md`.

Most of it rides the normal update: the sync script's bundle map now delivers `.codex/config.toml`, `.codex/README.md`, and the root `AGENTS.md`, and refreshes the hook scripts (`git-guard.py` gains a `--codex` mode; `mount-guard.py` is new) — so the pin bump plus `sync-executable-layer.py --from <old pin>` lands all of that with nothing extra to do. **One artifact can't ride the sync: the symlink.** The sync copies file blobs, and a symlink isn't one.

## Step 1 — create the skills symlink

From the brain's root folder:

```bash
mkdir -p .agents && ln -s ../.claude/skills .agents/skills
```

Verify with `ls .agents/skills/` — you should see the skill folders. Like every other change, it saves on its own: Parker Desktop syncs it, nothing to run. If `.agents/skills` already exists as a real directory (a team that hand-copied skills for Codex), leave their copy alone and note it in the digest instead: their copy is theirs, but it will not receive factory updates the way the symlink does.

## Not a repo step — tell the team once

If anyone on the team uses Codex: their first Codex session in the brain will ask to trust the project and approve the hooks (one time, per person). `.codex/README.md` in the brain walks them through it. Teams that never touch Codex can ignore all of this — nothing in the twin affects Claude Code.

Record `v17`.
