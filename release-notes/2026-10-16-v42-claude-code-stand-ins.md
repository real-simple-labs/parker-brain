# v42 — the brain names only tools a user can reach, and what Claude Code uses in place of chat-only ones (2026-10-16)

The method named tools that a brain's Claude Code session (a build, a routine, everyday work in a brain) never has: four that only Parker's chat agent has (`get_current_time`, `get_webpage`, `update_custom_working_memory`, `get_context_docs`), and three that users can't reach at all (`parker_file_system`, `search_web`, `ask_parker_agent`). 88 files of the method told Claude Code to use them, and `system/parker-tools.md` listed three of them as Parker MCP tools.

## What shipped

- **Tools users can't reach are gone from the docs.** `parker_file_system` is out of the 17 audit prompts and the tool inventory. `search_web` is out of the inventory and the 3 audit lines that used it. Those lines now run the web search only in Claude Code, with Claude Code's own `WebSearch`, and where no web search is available they mark that slice constrained (or, for the press read, keep to known URLs) instead of filling it. `ask_parker_agent` is out of the three ad-database specs, the scriptwriting `find-reference-ads` and `adapt-existing-script` processes, and the inventory.
- **The ad databases.** The internal favorites, Parker favorites and global AI-tagged ads databases have no tool available to users, so the specs and `parker-tools.md` say they are out of reach and nothing stands in for them. `find-reference-ads` follows the scriptwriting skill's source order with a tool for each source: the brand's own account scripts (`search_facebook_ads_semantic`), competitor and inspo scripts already in the brain, the niche organic library (`search_tiktok_videos`), then the public ad library (`search_competitor_facebook_ads`) and the swipe file (`search_swipe_file`). It names the source each candidate came from; it never calls a result a favorites or global-DB pick. The specs' tier order and their "Usage hooks" sections apply only once a tool reaches the databases, and the scriptwriting skill's source order (`SKILL.md`, `strategy.md`, `processes/INDEX.md`) ends with the public ad library and the swipe file instead of the global AI-tagged DB.
- **`system/parker-tools.md`.** `get_current_time`, `get_webpage` and `update_custom_working_memory` are out of the Parker MCP table, and the opening line no longer says the MCP fetches a known page. A "Chat-only tools" table lists each chat-only tool, what it does, and what Claude Code uses instead: the session's own date, Claude Code's `WebFetch`, the brain's own files, the brain's own context docs. The web-search section says Parker has no web search tool for prompts to name, and that Claude Code's own `WebSearch` can search in a Claude Code session. "In Claude Code" covers a Codex session too, except that Codex under Parker Desktop has no network, so no web search or page fetch, and a session with no date asks for it. The build-harness section allows a prompt to send Claude Code to its own tool only through those stand-ins and `WebSearch`, named as Claude Code's.
- **The date.** The freshness line in the shared expertise-core block (embedded in 73 prompts) and 10 more lines in `system/refresh-cadence.md`, `system/parker-system-map.md`, the `refresh-context` and `research-loops` skills and the two brain templates say "(in Claude Code, the session's own date)" after `get_current_time`.
- **Saves.** The tool paragraph of the 17 audit prompts says that in Claude Code the save is writing the output into the brain's files. `harvest-ideas` no longer lists `get_webpage` as a Parker MCP tool.
- **Context docs.** `ai-static-ad-generation.md` points Claude Code at the brain's own context docs.

Not changed: the open-loops rule that a loop answerable only by open-web search is constrained. That's a method call, not a tool name.
