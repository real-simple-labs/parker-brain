# 2026-07-31 — v14: the voice ships as a system prompt, the craft layer grows by fifteen docs, and the instructions talk to the model

Three merges, one theme underneath: make the things Parker is supposed to *be* structural instead of described. The voice stops being text in a file the model may or may not weigh and becomes the system prompt itself. The identity stops describing a character in the third person and starts addressing the model reading it. And the craft layer picks up fifteen docs covering ground it didn't have.

## What shipped

- **Parker's voice as a Claude Code output style** (#60). `.claude/output-styles/parker.md` carries the plain, warm, tenth-grade register into the system prompt itself, switched on by `"outputStyle": "Parker"` in the committed `.claude/settings.json` — here and in the brand-routines settings template every brain gets. `keep-coding-instructions: true` keeps the careful file-work discipline underneath, so the voice changes how Parker talks without loosening how Parker works. `prompts/_parker-voice-block.md` stays canonical; the style file is its hand-mirrored system-prompt copy, because a system prompt can't reference other files at runtime. Both are registered in `system/system-of-records.md`, and the audit compares substance rather than bytes — a voice rule present in the block and absent or contradicted in the style file is the drift. Shipping is mechanical: the onboarding runner stamps it at build, `scripts/sync-executable-layer.py` carries it in the bundle map, and the propagate script rsyncs it unconditionally.
- **Fifteen new creative-strategy knowledge docs, wired into routing and the owning skills** (#59). New ground: `visuals.md` and `static-ad-design.md` (the why-layer of the visual craft, and the fact that statics have hooks too), `ad-metrics-glossary.md`, `advertising-luxury-and-higher-price-points.md`, `advertising-to-older-audiences.md`, `seasonality.md`, `non-problem-solution-creative.md`, `creative-strategy-by-brand-size.md`, `creator-briefs.md`, `creative-consumption-analysis.md`, `new-product-launches.md` and `new-sku-launch.md`, `algospeak.md`, `legal-ai-ugc.md`, and `ai-animation-prompting.md` as a placeholder. Each carries its `summary`, so the generated DOC-MAP catalog — the one the prompt hook injects every turn — picks them up automatically. The second half of the PR is the part that makes them get used: `expertise-routing.md`'s per-task sections and the three owning skills (`ad-account-analysis`, `ai-ad-generation`, `scriptwriting`) now name the docs that have a clear owner, and a new **Brand-and-task modifiers** section holds the seven pull-when-the-brand-fits docs without pinning them to any skill's whitelist, per the "describe, don't pre-tag" rule. `best-use-cases.md` went from placeholder to a real menu and prompt library, and `ad-account-analysis.md` gained the funnel-stage read.
- **Identity is second person** (#55). The factory `CLAUDE.md`, the brand-brain `CLAUDE.md` template, and the canonical voice block now speak to the model reading them rather than about a character it should imitate. "You are **Parker**, a strategist" becomes "You are a senior creative strategist," plus one mapping line: the team calls this system Parker, and when they ask what Parker thinks, that's you. The character stays whole, just turned around. "Parker" survives only as artifact names — Parker MCP, `parker-brain`, `parker-system/`, `setup_parker_brain`.

## Reaching standing brains

Most of this rides the pin bump. The knowledge docs live in the mount, the craft catalog the prompt hook injects regenerates from their summaries, and the re-sync at the end of `/update-brain` delivers both halves of the voice layer — the style file and the `settings.json` that switches it on.

Two pieces don't, so **`migrations/v14.md` carries real steps**: the parker-voice block in a brain's root `CLAUDE.md` sits outside `parker-system/` and needs `sync-open-loops-core.py --scan .` to refresh, three third-person identity lines outside that block need a hand edit shown to the team, and if a brain edited its own `settings.json` the sync script leaves it alone — so the `outputStyle` key gets checked and added by hand in that one case, or the style file lands inert.
