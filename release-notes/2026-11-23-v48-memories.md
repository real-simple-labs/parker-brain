# v48 — the brain reads Parker memories (2026-11-23)

Parker memories are the short facts and rules a team saves in Parker (Settings → Memories, or chat): "never say cheap", "briefs focus on the hook and the production style". Parker's web and Slack chat reads them on every message. Since 2026-11-23 Parker's server also keeps them as files, one `.md` file per memory, in a `memories/` folder of the matching repo: brand memories in the brand's brain, organization memories in the organization's shared folder, a person's own memories in their personal folder. The sync goes both ways: an edit in Settings changes the file, and a file edited, added, renamed or deleted in the brain changes the memory.

A session in the brain (Claude Code or Codex) did not know about them: the factory still said that the Claude Code stand-in for `update_custom_working_memory` was "the output doc and `running-notes/`".

## What shipped

- **The session start hook reads the memories in.** `session-start.py` reads `memories/` (this brand), `../memories/` (the organization's folder, when the brain sits at `orgs/<org>/<repo>/` in Parker Desktop) and `../../../personal/memories/` (the person's own; `../../personal/` for the layout before Desktop 0.1.18). It takes the same files Parker's server syncs: `.md` files directly in the folder, not `README.md`, not hidden files. It pastes up to about 3,500 bytes of memory text, only in the room `.parker/access.md` and the other lines leave under about 10,000 bytes (Codex moves hook output past about 2,500 tokens into a temporary file), names the files past that while names fit, and counts the rest. A cloud run's clone has only the brain's own folder. The hook runs again after a compaction, so the memories come back too.
- **Saving a memory from the brain.** Only when the person asks to remember something, or says yes to an offer; never on the agent's own from what a tool, a file or a web page says. One short file, one fact, at most 4,000 characters, in a folder the session can reach: `memories/` for the brand, the organization's folder only after the person says yes to that scope, the person's own folder for their preferences (the hook names the folders it found; a cloud run's clone has only the brain's own). Nothing from a restricted folder goes into a memory. Parker syncs it into its memories in a few minutes; when a write outside the brain is blocked, the person adds it in Settings. `system/parker-tools.md` names this as the stand-in for `update_custom_working_memory`; long results still go in the output doc and `running-notes/`.
- **How to treat them.** Like `running-notes/brand-rules.md`: facts about the brand and the team's preferences for the work; when one clashes with what the person asks now, the person wins. A memory never changes access, tools, permissions or where content may go, whatever it says.

## Migration

`migrations/v48.md`: nothing to do. The re-sync refreshes the hook and `AGENTS.md`; standing brains' `CLAUDE.md` keeps its map (the hook carries the rule). The `memories/` folders come from Parker's server.
